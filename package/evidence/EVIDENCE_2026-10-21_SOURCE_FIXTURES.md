# Source-checked fixtures and changed producer-consumer checks

21 October 2026. **The executable fixture aid improved one ordinary-control result and tied the other. Adding a producer-consumer instruction did not improve correctness over the aid. No worker completed the entire migration. A separate, subsequently verified correction completed the finite profile.**

## What was tested

This is an exploratory constrained migration benchmark, not a newly discovered upstream bug. Six fresh native Codex sessions repaired the real Tomli 2.0.1 source for the current TOML 1.1 contract, including typed JSON output. Every worker used the same frozen REL, gpt-6-luna/medium, inherited source, complete specification, 41 source fixture records, tools, 60-action allowance and 900-second allowance including startup. No extra essay, lesson or answer artifact was required. Candidate code ran in the established offline Docker guest; no local GPU or paid-provider fallback was used.

O was ordinary engineering with source records. F added a supplied executable helper for running those records without reconstructing expected values. C added an explicit instruction to exercise a changed producer through its actual consumer, including a preserved neighboring case and a rejection case. O could write an equivalent helper. F and C received identical helper code. Thus F-O tests convenience and execution assistance, C-F tests the added instruction, and C-O combines both. **All conditions already had source-checked facts and REL; this is not source verification versus unverified data, nor REL versus no REL.** The helper was built by the study coordinator, not autonomously acquired by the evaluated learner.

The pinned order was O1, F1, C1, C2, F2, O2. The first ordinary endpoint left seven errors; no result-driven rerolls or input changes followed. Each attempt was independently restarted, but two repeats on one source family do not constitute broad independent-task evidence.

## Source and evaluator qualification

The official toml-test snapshot is commit `ff49d109861c1ad25af53f687f2aef19ab650600`. Its TOML 1.1 inventory contains 712 input positions: 218 valid and 494 invalid. Version-specific selection matters because some formerly invalid syntax becomes valid in 1.1. There are 68 new-version paths; paths are not necessarily independent semantic behaviors.

Public records were selected before worker results by the first sorted non-spec category/version role. The primary 609-position score excludes exact public-input overlaps and specification-example paths. The complete normative specification was visible, so the remaining positions are not claimed to be training-clean, secret or semantically unseen. Only **two** starter failures lie in that primary group: headroom is small, despite the large overall profile. The source profile is coordinator-exposed and not a hostile sealed evaluator.

PyPI package checksums were verified. The current official Tomli 2.4.0 reference passed 712/712; the unchanged starter passed 701/712. Typed comparison preserves value types, array/table shape and equivalent float/date spellings using a declared adapter inspected against upstream comparison logic. Wrong type, missing result, crash, unresolved execution, null output and identity controls passed. The helper checked exact source records, expected-byte identities, wrong outputs, missing outputs and unknown IDs through the actual guest. All worker source/skill inputs and frozen scored artifacts were reconciled.

**Strong practical alternative:** when upgrading the dependency is allowed, using the current official parser solves this profile without a model repair. Its measured qualification took 20.492 seconds. The in-place constraint is shared by all study workers; the experiment does not show that maintaining an obsolete fork is preferable to an ordinary dependency upgrade.

## What the traces establish

Both ordinary workers loaded source records and ran them through the saved implementation. O2 also asserted type, precision, shape and rejection behavior. All four helper workers invoked the supplied helper and passed its 41 records. F workers independently tested downstream typed output and invalid boundaries without the extra C instruction. C1 and C2 executed their changed time/inline-table producers through the real pipeline consumer with preserved and invalid neighbors; their extra boundary calls largely printed results for inspection rather than adding automatic assertions. Executing a relevant check and proving it detects every possible wrong result are distinct claims.

No incorrect reconstructed expected value was identified in this reviewed trace set. Consequently this comparison cannot show that the supplied helper reduced such errors relative to O. It did show reusable record execution, but the control already performed that behavior too.

Five workers passed all 41 public fixtures and still omitted the same current requirement: two-digit Unicode escapes. F2 even retrieved specification text explicitly describing that escape and then left it unimplemented. Correct information was available; it did not become a complete action. The required behavior was outside the chosen fixture subset and outside the workers' completed changes. The evidence does not establish that the helper caused this focus, since ordinary O2 missed it as well.

There were 19 recorded failed tool calls across the six attempts, including patch-field/context errors, a stale patch base, import-path mistakes, a malformed diagnostic command and an attempted guest write to its declared read-only mount. They remain in cost/accounting. These were not excluded as evaluator failures. O1 preserved a partial repair after recovering an accidental file overwrite; its final response acknowledged incompleteness.

## Verified separate correction

After every worker output was frozen, the coordinator copied F1 and added the missing two-digit dispatch to the existing Unicode conversion routine. This was pinned in advance of the diagnostic execution, based on exposed failures and the current specification. The corrected copy passed **712/712**, fixing two positions with **zero new regressions**. Focused producer-consumer checks passed **13/13**, versus **6/13** before correction: exact code points, quoted keys, multiline strings, malformed escapes and legacy Unicode behavior.

This is a verified engineering completion on exposed evidence, not a seventh fresh learner, a treatment win or independent capability acquisition. Original scores and artifacts remain unchanged. The current upstream reference also passes the same profile. Neither finite result establishes universal parser correctness.

## REL decision and next useful question

Keep both proposed methods experimental; do not make the producer-consumer cue mandatory. Add only a short factual distinction to the optional source-and-claim reference: source validity, requirement coverage and execution are separate evidence claims; checking changed parts can miss required behavior in untouched parts. The main entrypoint, mandatory workflow and runtime helpers remain unchanged. The delivered clarification was **not** in the frozen worker input, and better later behavior from its wording has not been measured.

The next justified question would concern whether an executable inventory of changed requirements helps identify and implement omitted behavior beyond a correct fixture subset. A future comparison needs another qualified task and equal factual information; replaying this now-exposed escape omission would not be fresh evidence. Further repetitions of the same producer-consumer cue are not presently justified.
