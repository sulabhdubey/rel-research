# Real-project observations and package correction

18 October 2026. Procedural evidence, not a matched performance experiment.
Predecessor commit: `10d49df9bb3365f2f7e128038a525738596b0977`.
The main entrypoint and all host/helper/test code remain unchanged.

## Findings and bounded decisions

Three convenience cases were reviewed retrospectively from one owner's Codex
environment. An earlier service finding changed a later investigation and repair;
interactive delivery needed follow-up on the recipient's route; and a numerical
validation workflow corrected mutable dependencies and incomplete test discovery.
The rejected scientific candidate, an existing failure and skipped checks remain
part of that record. Corroboration differs between cases, and exact historical
skill versions are unknown in two. Private project names, paths and chat excerpts
are not included here. These observations do not estimate REL's added benefit.

Two narrow clarifications were selected: check the recipient's intended route
early when it can invalidate delivery, and reconcile test identities when changing
discovery. Existing instruction-snapshot and lesson-application guidance already
covered the other findings; no duplicate rule or new mandatory form was added.

## Fresh application to an actual package

A separate agent received the staged skill and an offline package-delivery task,
without the parent diagnosis, private field cases or desired verdict. It inspected
the source inventory, ran the existing tests and lifecycle example, and found that
the delivery guide enumerated only 79 test methods. It omitted 24 existing offline
broker tests and one separately opted-in live integration test. The documented
route now uses complete discovery and explicitly leaves the live Docker opt-in
unset. No test bodies or expected outcomes were changed to achieve this correction.

The forward audit reconciled all 104 collected identities with actual unittest
starts: 103 passed and one live Docker integration case skipped. It also recorded
26 passing named subtests, which are not independent task trials. The lifecycle
example exercised seven fresh checker subprocesses and its expected drift and
retirement outcomes. Initial task-local audit instrumentation mishandled a Windows
subprocess argument; the failed observer output was preserved and the affected
checks were rerun after correcting the observer, without changing package code.
This is an observer defect, not a package regression. Staged reference edits also
caused the expected old-manifest mismatches before final versioning.

The independent application supports a concrete documentation repair and a working
audit procedure. It does not isolate the contribution of the candidate wording
from ordinary competent auditing. There was no matched old-skill worker, new model
benchmark, Docker engine, network request, or model-server call in these offline
checks. A skipped live integration test establishes no new runtime qualification.

## Delivery and reproduction

Use the [non-public source: delivery guide](https://github.com/sulabhdubey/recursive-evidence-loop/blob/507357e1d7a55335f9205134ad1c32ac4657b0bc/docs/DELIVERY.md) for the actual offline commands. Its complete
discovery command exposes case identities as well as totals. The existing lifecycle
example checks a recipient's runnable route, including saved-state readback in a
fresh process; synthetic lesson records do not demonstrate autonomous learning.
The package and core manifests bind the revised references and documentation.

The clarification follows the primary [Python 3.13 unittest discovery documentation](https://docs.python.org/3.13/library/unittest.html#test-discovery):
the start directory and filename pattern control collection, which imports the
selected modules. In this case, source inventory plus actual execution exposed
the omission; equal totals alone would not establish the same scope.

## Limits and next use

Treat these as scoped process corrections. They do not prove general skill
superiority, sustained self-improvement, reduced token costs or that adding text
prevents every recurrence. The recipient-route clarification still needs observation
on later interactive deliveries; this task qualifies an offline package route, not
a new live website. Historical field cases have no matched controls or complete
cost records. Preparation, reviewer tokens, human work, currency and energy are
not fully measured. Do not convert test counts into model reliability estimates.

On later use, retain a clarification if it prevents a concrete omission with
proportionate effort; revise or remove it if it causes unnecessary machinery or
does not apply. No shared entrypoint expansion is required by this review.
