# Interrupted import/export: ordinary-worker qualification

20 October 2026. Four ordinary workers; no REL learning comparison admitted.

## What ran

Two independent import repairs and two independent export repairs used
gpt-6-luna/medium, the same current documentation, an authoritative API
implementation, distinct public examples, offline tools, and a 60-action/
900-second budget. Workers received no REL or prior-episode text; the coordinator
used REL to research, qualify, execute and evaluate the study.

These were authored fault-injection tasks with real SQLite databases and files.
Exceptions occurred around commit, source-page replies and file publication.
The evaluator reopened storage and called the controller twice with fresh API
objects in one process. This was **not** an actual process kill, power-loss,
model-session restart or production-outage test.

Imports covered tenant/operation identity, changed intent, durable receipts,
duplicate effects and collateral data. Exports covered empty intermediate pages,
opaque cursors, stale progress, matching-size wrong content, foreign ownership
and partial publication. Final artifacts and stored state were checked.

## Result

All 240 case executions passed, across four worker attempts. Cases within an
attempt are not independent replications. There were no rejected tool actions
or unresolved scored cases. The initial controllers failed 20/48 import cases
and 44/72 export cases; those were fixture defects, not model baseline scores.
An independent formula-based expected state and a reference controller were
qualified before dispatch.

Both ordinary workers had to leave the same semantic failure class for a
workflow to qualify. Neither did. No later REL/equal-information/no-retention
arms were run, and reserved later cases were not executed. These tasks therefore
cannot currently distinguish added REL learning value. The result neither proves
REL superiority nor rejects experience-based learning generally.

## Verified corrections

- Added matching-size wrong-content coverage before any model or candidate outcome.
- Corrected a copied launcher's runtime binding and a newly enabled skill in the
  ordinary-control environment.
- Diagnosed a new active MCP server's oversized inventory response. Disabled it
  only for study processes and qualified the exact current disabled roster,
  including the thread-scoped startup boundary. No external MCP tool was called;
  user installations were unchanged.
- Retained six pre-inference stopped dispatches and one preparation assertion
  failure. None started a model turn. All four completed workers had verified
  empty skill inventories, disabled external tools and contained cleanup.

A no-thread preflight did not cover the thread-scoped inventory failure. The
host correction exercised that actual boundary; it did not relax the transport
bound or convert failed attempts into model successes.

## Recorded cost and limits

Four native turns comprised 42 provider requests: **755,658 tokens**, including
589,440 cached-input tokens. Uncached input plus output totaled 166,218.
Tokens per successful worker were 188,914.5, or 41,554.5 for uncached input plus
output. There was no extra model feedback turn. These are ordinary-worker costs,
not REL savings.

Summed worker dispatch duration was 682.8 seconds. The six pre-inference stopped
dispatches added 182.4 seconds. Other measured qualification and probe scopes
totaled 294.3 seconds. Concurrent intervals overlap; these are not elapsed
calendar time. Coordinator tokens, complete preparation/orchestration, money and
physical/remote-model energy remain unknown. Existing subscription admission
was used; no paid-provider API or GPU model inference was used.

The fixtures are author-built, the expected answers coordinator-readable, and
the runtime qualified for honest workers. Source families, process crash behavior,
concurrency, disk failure, intermediate visibility and efficiency under large
loads were not established. Orphan export cleanup was not a scored endpoint.
Actual guest versions were Python 3.12.15 and SQLite 3.40.1.

## Consequence for REL

The core instructions and helpers are unchanged. Existing REL already covers
research-first work, exact interface qualification, preserved failures, fair
comparison and no-change admission. This result justifies evidence and host-scope
updates, not another mandatory rule. Both candidates are closed; reopening needs
a distinct observed unresolved task and a reason retained experience can help.

The full local plan, sources, failed receipts, frozen artifacts, all verdicts,
cost ledger and verification remain private. This sanitized summary is not a
complete runnable research benchmark.
