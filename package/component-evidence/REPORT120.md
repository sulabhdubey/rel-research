## What is consolidated

The map binds nine retained components to their actual code/methods, state, assumptions, inputs, outputs, costs and counterevidence. It distinguishes symbolic acquired methods, convex numerical decisions/continuation, temporal-graph state/certificates, and range-bearing localization. These are useful but differently typed implementations. Graph closure cannot certify pose accuracy; an acquired numerical method is not automatically an observation model. Prior mathematics and Alien-inspired mechanism comparisons remain represented with their actual limits.

The executable reference bundles the directly compatible localization chain: ordinary robust filtering, both frozen acquired programs from Run106, and one equal-position/circular-heading mean for each acquired program. It preserves the existing numerical update loop and the two method JSON identities. Prediction accepts the declared measured inputs, known map and supplied initial pose. Evaluation truth is accepted only by a separate scoring function.

This is a source-independent software interface, **not source-independent performance evidence**. The caller must establish actual provenance. Metadata declarations alone cannot prove that measurements or maps were not derived from hidden reference data. Replay consumes each event causally, but checkpoint binding covers a complete fixed input record; it is not a qualified live sensor service.

## Actual fixes and executed checks

The extracted numerical update prefix matches the earlier AST. Three-filter predictions on the regression fixture also match the legacy implementation exactly; their scoring results agree. The reference runner produces five outputs from three measured filter executions, sharing the robust path honestly.

Testing found and fixed three engineering issues before delivery:

1. Resuming could mutate the caller's original checkpoint history. The wrapper now deep-copies checkpoint state before continuing. Repeated resumes preserve the saved input and agree.
2. A requested stop at or before saved time could silently return already-saved later rows; mixed-time filter checkpoints were accepted. Both are rejected explicitly.
3. A malformed saved state could raise an internal indexing error. State shape/finite checks now reject it at the interface.

All17 tests pass, covering required outputs and equal observation consumption, reference/future-input isolation, input/schema rejection, averaging/scoring arithmetic, checkpoint boundaries and repeatable restoration. Three unsuccessful attempts remain preserved. A separate integration check starts two actual child processes, saves and restores JSON state, and reproduces all five outputs and three complete filter states. [non-public source: INTEGRATION_CHECK.json](https://github.com/sulabhdubey/recursive-evidence-loop/blob/e775ee8b68a2db210641768024e9bdae3384dac0/examples/component-source-qualification/INTEGRATION_CHECK.json) records parity, versions, timings and identities. These are engineering checks on constructed inputs, not a new physical benchmark or evidence that averaging wins. The first integration receipt measured file identity only after restart, so its file-immutability claim was unsupported. That receipt is preserved as INTEGRATION_CHECK_INITIAL.json; the corrected check now hashes the file before and after the restart process. Continuity parity was unaffected. Each integration attempt also launches one example process, making six child processes across the two attempts; the latest save/restart check itself uses two.

Independent static review verified arithmetic/method identity, source scope and corrected checkpoint behavior against the saved tests. It did not independently execute the tests. Checkpoints remain trusted artifacts: input/method binding is not state authenticity, and a reference-span check does not establish reference accuracy or maximum interpolation gaps.

## Programme decision

The programme retains A1/A2 acquired state/methods, A3 numerical/temporal reuse, A4 useful input allocation111 and A5 conditional numerical/graph checks; A6 remains an unproved procedure advantage. The new component map separates four typed executable families instead of calling their union a validated architecture. Run119 averaging remains a scoped optional trade-off. Run120 makes its prediction/scoring interface reusable and repairs state continuity, but no independent empirical transfer or full architecture advantage follows. Twelve material cycles lack full learned-architecture advantage. The different next mechanism is source-appropriate observation-model adaptation, conditional on a real documented interface, rather than another uncertainty selector or forced frozen-transfer claim. Mathematical identities and certificate assumptions remain attached to the computations they actually describe; Alien-inspired diversity changes the proposed computational object, not the evidentiary standard.

Run121 should qualify the AAU range-only interface as an explicit adapted-method question: resolve the advertised README/configuration schema, tag geometry, odometry timing, map availability and LiDAR-reference dependence before numerical access. If those resolve, pin a strong ordinary range-only filter and a separately specified adaptation of retained methods; keep training/development/confirmation separate. Do not fabricate bearings or call the existing frozen methods compatible. If the source contract remains unresolved, finish the current evidence/paper synthesis rather than repeat another broad dataset search.
