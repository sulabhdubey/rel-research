# Run120 retained component and executable interface map

Nine retained components form several working families. They do not yet form one validated adaptive architecture. This consolidation traces current source files, saved methods, interfaces, state, validity assumptions, feedback and costs. `COMPONENTS.json` contains full SHA256 identities, exact artifact paths and per-file inspection scope.

No experiment, model session, raw dataset/reference array or private chat was opened or run by this component-map task. Historical reports support the recorded outcomes; current source checks support continuity and interface relationships. They are not independent replication.

## Minimal frozen localization reference chain

1. Supply one admitted recording object with a known authoritative landmark map, aligned command/measurement events and a permitted common initial pose.
2. Run the frozen Run119 trace with Run106's ordinary `robust` configuration and no acquired engine, retaining endpoint diagnostics with `keep=True`.
3. Run the same trace under the fixed host configuration with each exact adapted program, J1 and J2. Retain both replicas.
4. Extract each `checkpoint.rows` array and call `runtime.readout(robust_rows, acquired_rows, 'mean', None)` separately for J1 and J2. Mean does not read a threshold.
5. Only after freezing source roles, consumer trade-off and full cost boundary, score robust, both acquired outputs and both pairwise means. Scoring is separate from propagation and combination.

The endpoint schema is `[t, x, y, heading, total_covariance_trace, position_covariance_trace, last_preinflation_NIS, last_measurement_time]`. Position variance has units m²; angular variance must not enter the distance denominator. Equal mean combines Cartesian position and circular heading, falling back to robust heading on a circular tie. It returns no fused covariance. Both histories continue updating even when not selected. `keep=True` is part of the legacy capture contract because last NIS is taken from saved diagnostics.

The exact J1 program has five nodes and no custom persistent scalar. J2 has fourteen nodes and scalar `m0`. Both use the supplied physical EKF and causal host EMA/mean helpers; those helpers and physical state are not learner inventions. Process-noise multipliers act after the current observation. Command velocities are not actual-motion groundtruth; range is in metres and bearing in radians.

`runtime.robot` selects Run106 `data_repaired.py` for recordings 2/3/4/9 and Run107 `data_adapter.py` otherwise. These loaders normalize offline source-time order and contain MR.CLAM-specific path and identity assumptions. They do not establish verified network arrival order. `study.py:capture` and `evaluate_dataset` show the real legacy wiring; their historical guarded commands should not be rerun as new experiments.

The legacy loader derives common initial pose from reference, and `filter.run` computes later truth-dependent scores after its causal propagation loop. This remains source-traced offline reference code. The checked Run120 extraction now separates the scoring tail and source loader from the unchanged numerical loop, as described below. It accepts a declared supplied initial pose; excluding scoring truth does not authenticate initialization or source provenance.

A new independent source also needs a licence, units, map/frame, clock, identity mapping, observation availability/order, initialization and permitted-feedback contract. Its noise and kinematic assumptions need qualification. No independent empirical source qualified in Run120.

For Cartesian position the pointwise identity is:

`||((r+j)/2)-truth||² = (||r-truth||² + ||j-truth||²)/2 - ||r-j||²/4`.

The identity needs no independence assumption. It provides no tail guarantee or calibrated fused covariance. Normalized disagreement lacks cross-error covariance. Mean therefore remains an optional documented trade-off, with recording-level harms preserved.

## Checked Run120 reference package

`reference/rel_localization/` is a separate current package; the nine historical component count remains unchanged. Its direct interface is `runner.normalize(packet)`, `runner.predict(packet, checkpoints=None, stop_at=None)` and separate offline `runner.evaluate(poses, reference)`.

The exact prediction fields are `schema`, `semantics`, `duration`, `initial`, `odometry`, `observations` and `landmarks`. Schema is `planar-range-bearing-v1`. Initial pose is `[x,y,heading]`; command/motion inputs are `[time,forward_velocity,angular_velocity]`; observations are `[time,landmark_id,range,bearing]`; the map binds canonical positive integer-string IDs to `[x,y]`. Scoring reference is excluded from this packet. The declared contract requires planar unicycle motion, metres/radians, source-time seconds, independently measured motion and range/bearing, causal IDs, a map available before the scored period and initialization provided at start. The wrapper checks this declared metadata; it does not prove physical provenance.

Prediction returns five `[time,x,y,heading]` pose sequences—robust, J1, J2, J1-mean and J2-mean—plus three complete checkpoints, observation/rejection/engine counts, per-filter wall time and whole-bank wall time. The bank shares one robust history across its two means. Each individual deployed mean would still require its own robust-plus-acquired pair; whole-bank cost is a different accounting boundary. Evaluation accepts reference `[time,x,y,heading]` separately and rejects missing time support. It does not establish adequate reference sampling gaps or reference accuracy.

The builder's `BUILD.json` records an unchanged pre-scoring numeric AST prefix and exact J1/J2 method hashes. `INTEGRATION_CHECK.json` records exact legacy pose parity for all three filters on a synthetic fixture: 60 pose values per policy, with matching position MSE. Two actual isolated Python child processes saved and resumed the package; all five outputs and three complete states matched uninterrupted execution. The initial integration receipt claimed file immutability after hashing only after resume; that claim was unsupported. It is preserved in `INTEGRATION_CHECK_INITIAL.json`. The corrected check records `checkpoint_hash_measured_before_resume: true` and reruns the actual child-process comparison. Both integration attempts and their costs remain visible; no frozen numerical code changed. The continuity check uses two child processes, while the runnable example uses a separate third process.

The earlier mutable-checkpoint alias, retrograde stop/misaligned bank and malformed-state failures remain recorded. `IMPLEMENTATION_REVIEW.json` closes the two initial static-review blockers and explicitly distinguishes reviewer inspection from builder execution.
