# Run118 — adapting a saved method when identity rules change

**The matched pilot is complete: two ordinary and two REL sessions ran.** All four workers preserved the required identity/provenance results. The pinned complete contract passed for 2/2 ordinary and 1/2 REL sessions; the difference is an ambiguous audit counting unit. REL used 3.63% more deployment tokens, one fewer tool call and 2.33% less native worker time.

## What was compared

Four fresh subscription-backed sessions used the same gpt-5.6-terra model at medium effort, in the pinned ordinary / REL / REL / ordinary order. Both conditions received identical current task files, Run117's saved exact-key method and factual handoff, a finite read/evaluate/submit workbench, at most 12 calls and two evaluations, and a 300-second cooperative deadline. The REL arm additionally received the installed core SKILL.md, hash `42d417b1bb8ac2e63c13fa7c500d0d93b666064f0e0d25e553bfbd3bafcae285`. Supporting references, a full autonomous host and broad portability were not tested. Executed effort was measured, not forced equal.

The source has 304 records and a bounded 142-contact contract. The coordinator had already inspected and repaired this development task before fresh workers ran. Workers received neither that repair nor the verifier. The reference solution and T6 task remain unopened. This is four fresh sessions on **one** task, not four independent task families or external identity adjudication.

## Final checks and boundaries

Each submitted repair was rerun in new offline containers on original and reversed rows after all four sessions had ended. The common checker verifies complete email/phone-anchor groups, 426 source membership/provenance/phone fields for a complete result, named display requirements, audit counts and review notes. Four behavior probes test nickname, initial, distinct same-name identities and blank identifiers. Reversal contains the same facts. All eight original/reversed outputs pass the identity/provenance/phone checks and all four behavior probes. The second REL worker's final counter reports four selected phone/nickname insertion operations; the frozen checker requires three distinct affected contact groups. The initial task names phone_assisted_merges without explicitly defining that counting unit. Its README identifies three affected contacts, and the inspected public assertion requires three; in-turn feedback also names a group-count error. The frozen 2/2-versus-1/2 complete-contract verdict is retained, alongside the post hoc identity-only tie. This is an audit-unit compliance mismatch with an interface ambiguity, not evidence that REL merged the wrong people. No trial is repaired or rescored into the primary comparison.

The old saved method stayed read-only. No old-task regression execution was performed, so preserving its hash is not a regression pass. A declared adapt/replace choice and a read of the handoff do not by themselves establish that past experience caused the repair. The comparison isolates the added core instructions under these conditions; it does not isolate the effect of having history, since both arms had it.

## Decision and next step

Retain the ordinary implementation and close this identity-adaptation branch. The small observed differences do not justify more task repetitions, T6 expansion or generic REL wording changes. Ordinary work achieved the complete pinned endpoint in both sessions at lower total tokens; REL's one-call and small timing savings are preserved rather than erased. This descriptive pilot on one development-exposed task establishes neither a general REL advantage nor a general REL deficit.

The wider programme retains actual acquired methods and state (Runs85/102/103/106), selective information acquisition (Run111), ordinary incremental maintenance (Run112) and checked temporal reuse (Runs113/115). Run104 already integrated sensing, reuse, refinement and rebuilding but retained an accuracy/cost trade-off. The strongest next lead is Run106's lower mean error with extra large-error cases, not another contact-reconciliation prompt comparison. Mathematical validity conditions and falsifiers remain useful; source-specific assumptions must travel with them. Alien-inspired mechanism comparison should select a different executable explanation or representation, not repeat a closed threshold or selector branch. A1/A2 retained methods/state and A4 observation handling are the next bounded focus; A5 checking remains conditional and A6 procedure guidance stays frozen. The complete-architecture counter remains ten because this finishes the existing Run118.

The generic REL instructions stay unchanged: the verified defects were in host execution/accounting, and existing instructions already require preserving failures and checking source contracts. Evidence, current programme decisions and the private package are updated.
