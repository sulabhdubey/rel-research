# Study design checks for protected empirical evidence

Use this reference for a protected empirical claim with prospective source data, model training, development, or confirmation roles. The detailed checks later in this file apply only when their named source format, stage, mechanism, or claim is present. Adapt thresholds to the question; do not copy a prior dataset's numbers. Use the applicable fields of the [detailed run record](../assets/run-record.md) if no stronger ledger exists.

**Exploratory feasibility:** A bounded source-free, metadata, or authorized exploratory check may precede a full confirmation design. Declare its question, source and access authority, data role and exposed units, cost cap, stop rule, and claim limit. Record what it actually establishes; do not impose unrelated protected-run checks. Exploratory exposure can guide design but cannot later become fresh independent confirmation; reserve untouched, role-separated evidence for that claim.

When a complete-result or ceiling decision spans explicitly declared finite routes (such as public operations or input modes), reconcile those routes with the cases actually included. Use the existing case inventory when possible. The optional [route-presence checker](../scripts/coverage_audit.py) accepts a JSON case list and an explicit list of required scalar-selector objects: `python coverage_audit.py cases.json required.json`. It detects omitted declared routes; it does not infer requirements, confirm test execution, check assertions, or establish exhaustive semantic coverage. Do not invent selectors merely to run the helper, and do not install a runtime for an ordinary review that can inspect the mapping directly. An omitted route limits the completion/ceiling claim even when every included case passes.

For a comparison intended to improve error correction or later decisions, distinguish defects in the starting material from errors that remain after a strong ordinary worker has had the same task information, tools and budget. Reproduce the source problem, then check the intended baseline on the scored endpoint before scaling the comparison. Self-repaired intermediate mistakes, unsupported use outside a method's declared scope, and interface or evaluator failures do not by themselves establish a remaining reasoning gap. If the endpoint is saturated, retain that evidence and either choose a prospectively justified different task or test an explicitly stated cost, reliability or other nonsaturated outcome; do not quietly reduce the baseline's resources or relabel repetitions as independent hard tasks. Keep this feasibility decision separate from completing the user's ordinary work.

When judging a reusable method by amortized cost, give every decision-maker the same declared workload horizon, likely changes and restart conditions, or explicitly state that they are unknown. A small development probe is not the deployment horizon. Charge setup, learning, rebuilding and verification over that workload; use sensitivity ranges when its volume is uncertain. Keep acquisition, successful later execution and worthwhile deployment as separate outcomes.

When comparing approaches that retain executable methods or directly reusable procedures, include direct use of the existing artifact as a strong simple baseline if an authorized, proportionate route could satisfy the later task without another model call. Check the complete current contract, including changed scope and required outputs; unchanged bytes establish identity, not continuing applicability. Count original acquisition and later execution, adaptation and verification costs, with unavailable costs left unknown. If direct use is unavailable or cannot meet the contract, record that specific limit rather than forcing a replay. This conditional study-design check does not require a new benchmark for ordinary task execution.

Before protected content access for an independent effect or confirmation claim, specify:

- source identity, rights, format, participant/task inventory, sensor or document timing semantics, and an inexpensive metadata stop;
- exact eligible cases, exclusion logic, time or state boundary convention, missingness behavior, and the unit of analysis;
- how feasibility, training, development, and confirmation differ, including the exact members and which outcomes have already been inspected;
- causal information available at each decision and any offline-only annotation;
- candidate, strong simple and no-mechanism arms, matched resource budget, training selection, and a genuine negative control;
- primary comparison, uncertainty interval or paired analysis, per-person/task distribution, harm constraint, and stop/advance predicates;
- full resource ledger for the claim: direct calls and latency for a routing claim; calibrated wall energy including sensing, idle, updates and memory for a whole-system energy claim;
- independent implementation/specification checks and a failure receipt that closes downstream access.

When asking whether a procedure helps beyond additional effort, distinguish equal maximum allowances from equal executed work. Before outcomes, pin the cost dimensions, tolerance, comparison points, and unmatched-attempt rule. If using saved artifact checkpoints, select them from costs alone, reconstruct accepted changes against their recorded identities, and verify the final replay. Respect tool-request and usage-reporting boundaries; retain the neighboring cost bounds and report unmatched cases rather than selecting the best-scoring snapshot. Report total recorded usage alongside any uncached-token match, plus natural endpoints and failures. An early checkpoint with no implemented change or approximate token agreement does not establish equal cognitive effort or a general benefit. Use this design only when that comparative claim needs it.

When agents or processes share a protected study, assign custody for each role before access and verify actual isolation or an independently validated complete exposure ledger covering each actor's protected reads, writes, units, and time. Establish the ledger's coverage at an appropriate enforcement boundary; an application hook alone cannot establish completeness across a shared host. A role plan or shared filesystem path alone does not prove separation. Preserve any out-of-role access as an incident, mark the affected units exposed, and withhold an independent confirmation claim for them until fresh role-separated evidence is obtained; if access cannot be established, label exposure unknown rather than calling the holdout untouched.

Before calling an ablation causal, make its **primary** contrast perturb the named mechanism rather than merely compare against a broad baseline. Check whether two proposed controls become distributionally identical under their randomization. When state trajectories diverge, a nominally equal mask fraction, budget, or replay policy can produce different *executed* counts; define the per-step shared count or intervention source and verify exact matching with source-free paired fixtures. Preserve canonical baseline update semantics instead of borrowing a familiar algorithm name for a materially changed rule. Keep the mechanism contrast distinct from a practical comparison against a tuned, time-matched simple baseline, and pin a harm guard for the capability the intervention might suppress. If these controls cannot be specified, narrow the causal claim before sealing.

Before sealing a downloaded-source admission, inventory the actual package members and write an operation-by-role matrix: which bytes may be inspected as metadata, hashed, decoded, used for fitting, scored, or exported. Check that every proposed predicate is executable under that access contract; pin when each split is materialized and its exact output path. Define duplicate and cross-role identity on the policy-visible **input** independently of target labels when the same input could carry different labels; a hash of input-plus-answer can miss leakage. Keep lossless input identity separate from a conservative task-family key when altered representations may carry the same task information. Use the [equivalence-key checks](operational-checks.md), preserving original inputs and labels and challenging the grouping with both meaning-preserving variants and similar-looking cases whose order, literal content, multiplicity or references change the answer. Rehearse source-free counterexamples with an unexpected inert member, a check that needs disallowed bytes, identical inputs with conflicting labels, and a staging directory whose inherited permissions differ from the final workspace. After materialization, verify hashes and read access under the intended downstream identity. A writer's successful receipt is not proof that the next stage can read the artifact.

Verify the **meaning** of any source field used as an instance ID, class lookup, time axis, or role key from primary schema documentation, its actual shape, and its relationship to the source's instance index; a suggestive field name is not evidence of its semantics. For linked or virtual container formats, use source-free alias fixtures and check that permitted paths cannot resolve to forbidden outcome bytes before reading values; reject unapproved external storage. A duplicate fingerprint must preserve every accepted **policy-visible input** value across declared dtypes; challenge conversions with source-free boundary integers and float widths rather than trusting a hash computed after lossy casting. Bind the exact reader dependency and code versions in the stage receipt, and compare post-read and pre-read source digests when concurrent mutation could change the object being audited.

For multi-document or history-backed cases, define role separation over **every policy-visible content unit**, not only case IDs, labels, or annotated support. Before protected text or outcomes are opened, inventory direct and transitive reuse of documents, turns, and other displayed context across feasibility, development, and confirmation; use stable identity or content fingerprints suited to the source. Split, cluster, or exclude linked cases under a pinned rule, and have an independent check replay the resulting membership. Distinct targets can still share a displayed distractor that carries information across roles.

An oracle with a different action history or information set is not an upper bound for a causal controller. An exploratory analysis on exposed data can diagnose and design but cannot restore its independence. A larger or newer dataset does not by itself create information value; its measured support and endpoint must match the question.

For a selective policy with multiple valued outcomes, pin whether harm limits constrain **development selection** or are only a final rejection check. If feasible candidates exist, choose among them under the declared rule; an unconstrained winner that fails a harm limit is not evidence that every candidate fails. If a policy's actions determine which later observations exist, replay each policy with its own observable state and charge any refresh work before claiming sustained savings. A full-feedback replay can compare one-step rankings, but must be labeled shadow evidence rather than a closed-loop benefit.

Before protected content, try to falsify each pass predicate with source-free fixtures: check denominators and conditioning for tautologies, and check whether the source's annotation or measurement process can identify the quantity named in the claim. If independent replay is required, pin a comparable serialization of claim-critical unit identities (including timing when timing matters) and compare its digest as well as counts and status. Aggregate agreement alone can conceal different underlying events.

Challenge the **direction** of minimum-event support rules with source-free zero-event and rare-event cases. A minimum observed harm count may be needed to fit or assess a harm predictor, but it is not a safety guarantee: it can reject an intervention solely because it harms fewer cases. Separate that estimator-support failure from the intervention's outcome, and, where safety is the question, predeclare an uncertainty bound on the harm rate or loss instead. If this defect is found after development outcomes are exposed, preserve the original stop and use fresh independent evidence for a revised admission.

For a multi-stage workflow, inventory endpoint labels or outcomes for every branch and verify their join to the policy-visible case identity before claiming end-to-end selectivity or savings. Controls labeled only for an early-stage decision can test that stage, but cannot establish missed downstream harm or a final benefit for skipped cases. Keep the stage-level and end-to-end claims separate.

For a claim that depends on a source, time, or state axis, pin counterfactual probes and invariant controls among the selected policy-visible cases. Before model scoring, independently reconstruct the expected flips and non-flips from rendered inputs, with minimum counts fixed before outcomes. Private oracle fixtures and scenario labels alone do not prove that scored inputs exercise the mechanism. If valid counterfactuals cannot be formed, narrow the claim to observational support.

For a conditional intervention, test the trigger with qualifying, boundary, and clearly nonqualifying source-free examples on every relevant side of the condition. Record a compact trigger reason when later diagnosis depends on knowing *why* computation or an action was bought; final action and work totals alone may not identify the cause.

When arms claim different compute, sensing, retrieval, or update budgets, verify their *executed* work before protected scoring. A source-free fixture should exercise every named budget (including intermediate values), and the runner should reject a row whose measured work contradicts its arm contract. Keep diagnostic or shadow work separate from the work charged to the chosen action. An arm name, configuration value, or equal nominal budget is not evidence that the work actually happened.

Before sealing an executable for a staged run, exercise the entire producer-auditor-admission handoff with source-free artifacts. Pin exact filenames, row schema, top-level pass/stop status, digests, selected parameters, and failure behavior; make the downstream guard reject a missing, stopped, unaudited, stale, or already-started prior stage. Revalidate every earlier selection or artifact that a later scorer still reads, not only its immediate predecessor. Unit tests for each component do not prove that the components agree on this contract.

Run that complete source-free handoff through the production writer and independent auditor entrypoints from the intended working directory. Preserve the full observed transport-event shape and the writer's persisted path/reference forms. Simplified usage fields or rewritten absolute paths do not establish compatibility with the protected run; require the exact-format handoff to pass before exposure.

For a pinned model runtime, rehearse external API return shapes and launch contracts on local, source-free inputs before spending a feasibility call: tokenizer/chat-template output type and token IDs, tensor shape, fixed worker arguments, isolation, and process-control identity. A syntax check or mocked adapter is not enough when an installed dependency can return a different container. Keep a failed pre-forward attempt, its log, and its disposition distinct from a model outcome; retry only after establishing whether any inference or protected data was exposed.

When sealing an executable inside a virtual environment, distinguish its **invocation path** from its resolved binary target. A symlinked `venv/bin/python` may hash to the same system interpreter as `/usr/bin/python`, yet invoking the resolved system path can lose the virtual environment's packages and change runtime semantics. Bind both paths and the target digest, preserve the intended invocation path in the exact child command, and exercise that command in a source-free stage before protected training.

For a staged training/selection program, a receipt hash proves custody, not that selected values were calculated correctly. Before final fitting consumes a training-only selection, independently replay the stated selection rule and all declared candidate cells from bound checkpoints and role-limited outcomes. Before held-out scoring, inspect saved numeric model/policy artifacts for exact key, shape, dtype and finite values with safe deserialization, in addition to their file hashes. A downstream consumer's own validation is useful but is not an independent audit of the producer.

Match a runtime admission estimate to the **actual executable job boundary**. If the scorer runs every pass, seed and case in one process under a per-process wall guard, its reserved total projection must fit that guard; a longer aggregate allowance is valid only after a source-free-tested sharding and exact-order merge exists. Bind the passing screen receipt and guard to the held-out release. A warmup subreceipt or an unexecuted shard plan cannot admit the full evaluator.

When a guard receipt authorizes protected access, verify that it guarded **this exact job**: its command targets the same contract and output receipt, and its bound input/code files have the expected pre- and post-run hashes. A generic `pass`, zero exit, or isolated-network field from a different job cannot release the next stage. Rehearse a swapped-but-passing guard receipt as a source-free negative fixture.

Before any held-out raw or label read, verify all training-only dependencies the scorer will later consume: selection, model and policy artifacts, safe numeric content and semantic digests, warmup and runtime admission. For a role selected by participant or source metadata, prove that the release contains **every** eligible source row, not merely that each released row belongs to the role. Use a source-only exact-row witness and an independent export-time comparison. The later label handoff must inherit that complete row binding; confirmation feature access needs the same prior gate as confirmation labels.

For persisted policy tables and report fields, distinguish effective inference state from explanatory artifacts. Recompute any table claimed to encode an online decision rule and compare its reachable cells to the effective implementation, or label it unused. Crosswalk the planned per-class, subgroup, overflow and cost evidence to the final persisted report before protected scoring; row-level raw fields alone do not satisfy a report claim.

For a resource claim implemented through composed readers and model calls, place the **primary** timer around the complete declared work boundary, including per-case adapter or cursor creation, raw input conversion, decisions, selected updates and final readout. Use the same outer timing boundary for every comparator and full-work arm. Inner phase timers may diagnose cost but cannot substitute for the inclusive timer; test the boundary with a source-free adapter whose construction deliberately consumes measurable CPU time.

Exercise the independent auditor on complete source-free rows from **every arm family**, especially a cheap control that omits model-only diagnostic fields. Match optional-field handling to the producer's row schema. A passing audit of only the computational arm can hide a schema exception on the first control row, leaving an otherwise completed protected stage unable to admit its successor.

For a multi-batch protected run, the independent auditor must enumerate the **actual** call, skip, admission, and account-snapshot artifacts, then reconcile them with the planned sequence and final receipt. Recompute per-batch attempt limits, account predicates, token totals and unknown-usage reservations from the saved bytes; check that each admitted snapshot precedes only its assigned attempt slice. A digest of listed receipts cannot establish that no unlisted call occurred. Test rejection of an extra call, extra admission, reused or invalid snapshot, and unexpected tool event on a complete source-free stage before protected exposure.

If an auditor defect is discovered after a protected stage is scored, keep the scored rows, scorer, metric and threshold contract, gate, first failed audit, and original pre-stage seal immutable. Pin a narrowly scoped custody-only auditor correction and its exact diff before replay; test it on source-free examples, then replay the same protected rows and gate without rescoring. Check the scored-row, scorer, metric/threshold, and gate bindings against the original seal before and after replay. Bind the original failure, corrected auditor hash, both audit results, unchanged bindings, and downstream admission in a separate post-stage attestation. Check the corrected auditor hash at later stages and disclose that the first audit failed. A change to scoring, a scientific validity rule, protected inputs, or thresholds needs fresh independent evidence; the replay does not make the scored rows fresh confirmation.

Treat a deterministic protected random-stream value as protected content even if a test only compares hashes and prints no value. Source-free tests must use a separate fixture namespace and assert that guarded protected generators deny access before hashing. If a protected stream is touched early, preserve the original seal and incident, retire the affected stream, choose a fresh domain or holdout, and reseal prospectively before scoring; do not call the original stream unopened.

Match each claim to its uncertainty analysis: a paired interval against one frozen comparator does not establish inferential superiority over every other arm, and a stress threshold without an interval is a prespecified observed result rather than statistical noninferiority. Keep descriptive rankings and measured host costs explicitly descriptive.
