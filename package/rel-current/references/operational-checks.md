# Operational checks for evidence-intensive runs

Use only checks whose stated trigger applies to the current work. These checks were learned in research, software, external-API and hardware studies; they are not universal requirements of the recursive loop.

## Changes to test discovery

When changing which tests run, compare the expected and actually executed test
identities, using paths and parameter identities where available, across relevant
file types. Reconcile additions, removals, duplicates and skips; equal totals or a
green result can hide an omitted test. Preserve earlier failures and distinguish a test excluded from
the declared scope from a repaired behavior. Keep saved test artifacts from
accidentally entering executable discovery, without deleting historical evidence.
This check applies to discovery changes, not every ordinary test rerun.

## Execution lifecycle in an evaluator

When a judge imports, restarts or batches executable submissions, match that lifecycle to the declared task and the worker's execution interface. Repeatedly re-executing an entry module while retaining its dependency state can introduce failures absent from ordinary use. Before attributing such failures to the submission, reproduce the load/call sequence with a small independent fixture, including repeated calls and a relevant rejection. Correct the evaluator at that boundary; do not require a candidate to survive undeclared reloads. Preserve original scores, replay unchanged artifacts and selection rules, and label any result-informed correction as reanalysis. This conditional check does not require restart testing for every ordinary code edit.

## Advanced feasibility, protected evaluation and external interfaces

- Audit information value. Ask: What decision will this run enable? Which fresh observation could reverse the decision? What does it cost in data, compute, money, time, and scarce holdouts? Prefer a cheap metadata/source check when it can rule out a full model run.
- Before testing a selector between rival worlds or mechanisms, compare the law of observations available by the decision endpoint, including observations from allowed interventions within the pinned budget. If the rivals remain indistinguishable, derive the attainable information bound and stop or change the question before protected data is generated; if an intervention can distinguish them, pin its cost and when its evidence arrives.
- Before attributing a benefit to persistent weight updates or storage location, construct the strongest legal fast-state or source-bound cache under the same lifecycle and resource budget, including future updates and resets. If it reproduces the updated predictor and decisions exactly, do not claim a quality benefit from where the state is stored; pin a real memory, lookup, persistence, or compute asymmetry and test it against that comparator.
- Pin the question, source/interface, eligibility and units, role separation, baseline tuning rights, cost accounting, primary metric, thresholds, stop rules, and claim boundary **before protected evidence is opened**.
- Classify each stop rule as an integrity check, source-support check, safety/runtime admission, pragmatic triage rule, or scientific futility bound. Challenge its semantics, denominator, measurement resolution, and boundary cases with source-free counterexamples.
- If an oracle or support screen controls stage advancement, optimize the declared endpoint under the actual per-unit quotas and denominators, and compare only controls constructible at that stage.
- For a safety-critical monitor, measure its actual sensor refresh, startup and tail latency over the expected duration; cross-check implausible readings against an independent query, preserve the raw trace, and pin the response to missing or stale samples. A requested polling rate is not proof that the sensor refreshes at that rate. Bind the initial release and later work permits to the latest validated sample under one admission state.
- Across operating systems or processes, measure freshness in one monotonic clock domain or calibrate clock offset and uncertainty before comparing timestamps.
- For a fast-changing hazard, bound the indivisible work unit and control-path delay, place a fresh expiring permit at the point of effect, and keep the sensor stop path live while other control calls block. Label a first-unit bound that has not been measured as an assumption; a later ACK cannot make it a prior guarantee.
- For a safety-critical monitor, a short unit test does not establish long-run telemetry reliability.
- A claimed futility bound must cover the candidate's information, feasible action history, carried state, budget, and endpoint; a failed triage rule does not reject the mechanism.
- Record a digest or immutable version of the plan and code where this matters.
- Where a protected run depends on pinned files or serialized receipts, independently hash **every declared byte-addressable prerequisite** against its actual bytes and run a source-free byte roundtrip for claim-critical output on the target host before execution; bind non-byte runtime or service dependencies by version, configuration, or observed receipt and state what remains uncertain. A copied digest or in-memory serialization test is insufficient.
- Before sealing a long producer or audit, exercise the **postguard terminalizer** against a source-free fixture using actual serialized JSON types, pinned digests and intentionally changed fields; passing child tests does not prove terminal release logic.
- If a producer, guard, or independent auditor crosses OS or path namespaces, exercise its exact entry point on every actual execution host against a source-free receipt and rehash each fixed binding there; a path that resolves on one host is not evidence that it resolves to the same bytes on another.
- For Python source-bound workers, a `.py` digest and `-B` do not prove which code executed: `-B` can still read an existing `.pyc`. Before Python starts, use an allowlisted environment and a fresh private empty bytecode-cache location with writes disabled, then verify source imports and bind the launcher, runtime and effective policy.
- For format-sensitive consumed inputs, check the encoding, newlines and schema of the **historical pinned bytes** before applying a parser; a new output-format contract does not retroactively change accepted inputs. Distinguish the declared record delimiter from legal characters inside a record: a display-line separator inside a quoted string need not end a serialized record. After repairing a reader, recompute affected measurements from preserved source bytes and verify the saved outputs; changing an error flag alone does not recover the evidence. For representation-sensitive edits, derive literal arguments from the current decoded content rather than a quoted display; verify the exact operation and affected output.
- Before releasing a protected evaluator, crosswalk every pinned endpoint, harm, diagnostic and cost field to the **final persisted receipt**, exercise the complete schema and boundary cases on source-free input, and obtain independent review; a correct score function alone does not prove the required evidence will be reported. Use [the run record template](../assets/run-record.md) if the project has no stronger ledger.
- For a cross-fit or stacked pipeline, trace the training membership of every upstream fitted component that produced calibration inputs; exclude the evaluation unit from those components wherever the downstream result claims an independent evaluation.
- When a study's unit of independence is an underlying entity, define and check its equivalence key before protected results are opened. Inventory same-key records both within and across roles; record IDs alone may name repeated versions of one entity. Exercise source-free fixtures with different IDs but equivalent content, and with equivalent content but different labels or observations. Validate the key against the domain: identical generic content need not identify the same entity. Pin whether such records are clustered, merged, excluded, or cause a stop; apply that choice consistently to source-support counts, selection, and uncertainty estimates. If an unplanned collision is found after protected results were opened, preserve the original gate outcome and label any repaired calculation post-hoc until fresh independent evidence tests it.
- For a local-first operator tool that reports evidence completeness, bind each entry to the project, run, and scope it describes, and require a declared coverage inventory before a complete result. Exercise changed context, omitted scope units, clearing an answer, import replacement, and unreadable local storage with source-free cases; a saved record is not proof that it still applies to the current scope. When a rerun can supersede earlier operator checks, preserve unresolved failures unless the replacement explicitly identifies the prior run and retains its rule and coverage contract. Challenge a clean rerun with a removed rule and a different input population; equal totals or a newer timestamp cannot establish resolution.
- For performance or energy comparisons, pin cold/warm cache and residency, thermal/frequency state, and competing workloads. Identify the suspected bottleneck in a phase-resolved baseline before changing it; interleave matched controls when state drifts, retain failed trials, and distinguish throughput from measured wall-energy gains.
- Before a compute-feasibility admission, crosswalk the actual executable stages to the estimate: repeated input validation and loading, preprocessing and batch preparation, checkpoint writes and rehashes, process starts, full inference and update paths, and independent audit. When worker and verifier stage or access inputs differently, qualify each actual path under its declared limits; a passing reference run does not qualify the worker path. Reuse applicable existing evidence rather than repeating a covered check. Time or conservatively bound each material path on source-free inputs; factor shared model passes from cheap post-processing grid choices. For streamed or serialized work, match the production iteration order and buffering/flush strategy; matching record counts and byte totals alone does not transfer I/O cost. An omitted material path keeps admission closed even if the estimated subtotal is below its cap.
- For a multi-stage study, draw the evidence and authority dependency graph before costing it. Check that every stage's inputs already exist and that the graph has a valid execution order; include selection, independent audits, post-guard terminal verification, and downstream scoring as separate nodes when they occur at different times. An in-guard child success is not an independently guarded pass. Measure compute probes through the same fresh launch policy intended for production; record configured numerical-library pools, effective operating-system thread count, process CPU versus wall time, and peak virtual address as well as RSS. Remeasure when the launch policy changes. When a launcher delegates to another process, identify the worker and relevant descendants before attributing its counters to the task. Reconcile sampled counters with worker-side evidence where available; near-zero launcher work while a worker is busy is a coverage failure, not an efficiency result. State which processes and sampling intervals were covered, and preserve missing historical measurements as unknown.
- For every authority role, derive its exact input-path inventory from fixed code or a frozen contract and compare the live guard bindings with that inventory. A launch seal cannot authorize inputs by declaring its own list. Exercise missing, extra, linked and changed inputs separately in source-free and production-role preflights before either role can release protected data.
- When role-dependent metadata is carried in parallel arrays or positional tuples, bind each value to a stable subject or task ID and independently replay that mapping in the actual execution order before sealing; a matching total or length does not establish correct membership.
- For a worker claiming source or label separation, record its actual workspace-controlled file opens, compare them independently with the fixed role inventory after execution, and test rejection of an unexpected path or alias.
- For a prelabel gate, trace the reads of every verifier it calls and check prerequisite numeric and role terminals before any verifier that opens or hashes label or target shards; exercise a failed prerequisite with an observed-zero-protected-open fixture.
- When tracing a worker's file opens, an application-level hook on a shared host is evidence about that run's observed opens, not OS-enforced file isolation or a complete ledger of other actors' access. A paper role assignment or shared directory does not establish custody across agents or processes; use actual isolation or an independently validated complete exposure ledger with appropriate enforcement coverage before claiming protected roles stayed separate.
- When protected model calls depend on an external CLI or transport parser, first run one bounded, non-benchmark canary through the exact sealed command and both producer and independent parsers, within the authorized call budget. Require a completed response and only diagnostics and tool events allowed by the sealed interface contract; reject unexpected events. Record reported token usage when available; otherwise label it unknown and verify a predeclared conservative reservation or separate accounting receipt that bounds spend before protected input. Keep the canary's cost separate in cumulative accounting, and stop before protected input if the interface contract or spend bound cannot be checked.
- When an asynchronous or changing inventory supports a completeness-dependent claim or gate, distinguish a provisional observation from a complete view. Use the interface's declared readiness or terminal criterion, which may be documented behavior rather than a particular field. A documented stable unpaginated view can be complete without cursor fields. When the interface declares pagination, follow its cursor contract to termination and reject missing or repeated cursors only where that contract requires them. Preserve the raw responses needed to audit the interpretation, and leave any required missing or inconsistent value unresolved. A clearly scoped provisional observation may support an action that does not require completeness. For a new or changed adapter, exercise the actual working path once, retain a stable unpaginated control when applicable, and test only relevant late, incomplete, or pagination failures; repeat qualification when the interface or adapter drifts, not on every lookup.
- When multiple agents or workers share an authorized paid-call cap, define whether it is team-only or account-wide and identify every in-scope spender. Atomically reserve a predeclared conservative cost bound for each uniquely identified attempt in one admission ledger covering them before dispatch, or use a provider-enforced hard limit or isolated budget for the same scope. Reconcile actual usage and failed attempts; keep unknown usage reserved at its bound until independently accounted for. A per-worker balance check cannot prevent joint overspend. If shared admission is unavailable, serialize through one custodian only if every in-scope spender must use it and every attempt is recorded; otherwise stop further calls under a strict cap rather than claiming control over outside spenders.
- Pin malformed-completion handling and no-retry accounting before protected model calls. A passing canary checks the interface, not the scientific hypothesis or its reliability rate.
- If protected calls require long-context or multi-item structured output, use the same sealed output schema, batch cardinality, and a near-worst-case synthetic prompt and response envelope in the canary.
- Before a one-shot external API acquisition with a fixed source cohort, use a bounded **non-candidate metadata request** through the actual production client when the API offers one. Bind the canary receipt and later acquisition to the same client-code digest, and preserve the request, decoded response bytes, parse result, timing, and raw-byte hash. A successful fetch checks the live TLS/response path only; exercise timeout, redirect rejection, pagination, warnings, and malformed responses with source-free fixtures or documented limits. A live metadata canary does not prove candidate query semantics, and local mocks alone do not establish wire compatibility. If no non-candidate request exists, treat the first candidate request as a separate transport admission and keep any exposed IDs or content as discovery evidence after a repair, never a fresh confirmation cohort.

## Repair and runtime-stop details

- Fix an implementation or guard defect when it is found **before** the affected protected evidence is opened; test the repair and reseal changed artifacts. If discovered after exposure, preserve the affected result as invalid or limited and require fresh independent evidence for a revised producer, scorer, metric, threshold, or decision rule. A custody-only auditor defect may follow the narrow immutable-evidence replay contract in [study design](study-design.md); that replay cannot validate a revised scientific result.
- Audit an activated stop rule before accepting its interpretation: separate a correctly implemented negative result from a flawed rule or implementation. Fix a discovered rule defect before affected protected evidence is opened, then test and reseal. After exposure, preserve the original stop and any defect finding; test a revised scientific rule only on fresh independent evidence. The custody-only auditor exception above preserves the original failed audit in a separate attestation. Do not lower a sound threshold, relabel cases, or reuse inspected people/tasks as fresh validation. Continue with unaffected research, a different prespecified branch, or a new independently designed study when useful.
- For a safety/runtime admission stop, record the failed measurement and preserve any completed evidence. Distinguish a measured unsafe state from failure of the monitor itself. Resume the same sealed implementation only after the prespecified condition recovers and a fresh admission passes. Operational batch size may shrink without inspecting outcomes only within a prespecified range that leaves outputs, selection, and analysis unchanged. A size change outside that range needs a tested, resealed plan; if it can alter outputs or the estimate, treat subsequent evidence as a separate branch. If the monitor repeatedly loses samples or exceeds its deadline, repair and reseal the instrumentation before more protected work rather than relying on repeated starts. If recovery fails, keep the partial result and design a separately sealed branch instead of mixing devices, sources, or changed thresholds into one estimate.
- When a runtime hazard persists after work is paused, measure a zero-work baseline and verify the pause through actual process state and CPU-time or device-work counters. Separate workload contribution, stored heat, competing work, sensor faults and observer overhead; a commanded pause or zero utilization snapshot does not identify the cause. Before repeated smaller retries or a higher ceiling, show that the controlled actuator can materially affect the hazard. Quantify any replacement monitor's cost and missing/stale fields, retain raw invalid values, and qualify its required measurements before use. A duty controller cannot establish a sustainable operating point from a baseline that never demonstrably cools; preserve that operational limit without treating it as a mechanism failure.

## Interactive timeout and rendered-state checks

- For stateful or effect-producing work, test complete operation sequences as well as individual operations. A new attempt or transaction ID does not resolve an earlier uncertain effect. Before a potentially harmful or non-idempotent repeat, reconcile current effects against intact authoritative state independent of the new attempt; if evidence is missing or inconsistent, keep that repeat blocked. Read-only observation and verified idempotent recovery remain within their existing authorization.

- When a caller times out or cancels, verify the callee's actual work, lock,
  connection, and worker lifetime. A returned timeout is not evidence that work
  stopped. Exercise blocked admission and real expensive work separately; assert
  that the intended path was reached, resources were released, incomplete work
  was not cached as success, and an explicit retry can recover. Share one deadline
  across retries and scope units. Keep cooperative OS/I/O limits explicit.
- Trace the full caller fanout: bounded child requests can still multiply total
  work through repeated discovery, retries, or concurrent views. Count actual
  admitted work at the workflow boundary on a small multi-item fixture. When
  deferring duplicate or over-budget work, retain known identities and unresolved
  failures; missing coverage cannot supersede a prior failure. Verify admission
  is released after exceptions and explicit retry still works.
- Close a failed gate by retesting its original contract. A faster metadata or
  bootstrap endpoint does not replace failed deep verification. Preserve the
  negative receipt and report deferred coverage without inventing a verdict.
- For important UI states, inspect rendered desktop and mobile evidence and
  assert viewport bounds where needed. A DOM visibility assertion can pass for
  content hidden beyond a horizontally scrolling container. Keep the observed
  failure as a regression case rather than weakening the check. Cross-check
  repeated verdicts in banners, summaries, and status bars for contradictions.
- When a built artifact is the deliverable, compare its actual member inventory
  and bytes with the intended source set. Deleted source assets can remain in
  reused build staging. Preserve the failed package, rebuild cleanly, and verify
  the installed artifact rather than relying only on source-tree checks.

## Exact-caller measurement-adapter checks


Before acquiring external or protected results for a changed measurement adapter,
run synthetic response bytes through the exact transport orchestration, parser,
conversion/comparison caller, summary, and serialized/reopened report. Unit tests
of the helpers alone do not exercise argument wiring. Include a wrong-arity
mutant that must fail, plus a type-valid wrong-result mutant that known synthetic
outcomes must reject. Assert that malformed early evidence prevents subsequent
transport. Synthetic preflight proves wiring, not physical accuracy.

Agreement between endpoints sharing one provider or implementation is an
internal-consistency check, not an independent truth source. At discontinuities,
check authoritative definitions separately. If that independent check is added
after seeing results, label it post-hoc and pin the next contract before using
it as a confirmation gate. Preserve the original failed gate; do not rerun until
agreement and silently promote that agreement to correctness.

## Semantic conversion certificates

For a certificate covering a unit, time-scale or coordinate conversion, replay
its declared numerical relationship and check the input convention, source
identity, effective interval and coverage expiry; finite plausible values alone
are insufficient. Exercise independently documented numerical anchors,
before/at/after boundaries, forged finite values and older saved payloads.
Withhold certification outside documented coverage instead of silently
extrapolating or turning an unavailable comparison into zero error.
